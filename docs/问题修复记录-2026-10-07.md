# 用户反馈问题修复（2026-10-07）

## 待办切回课表后底栏抬升、下方大块留白

截图中的课表仍有内容，异常集中于底部导航和页面可用区域。用户暂不确定此前是否正在输入，当前没有可连接的微信开发者工具自动化会话，因此未在原设备复现，不能把键盘问题认定为已证实的唯一原因。

代码中存在两处与截图现象吻合的风险：

- 自定义底栏把 `env(safe-area-inset-bottom)` 直接用于底部 padding。若原生窗口在输入或切换页面时返回异常的环境值，底栏背景会被撑高，按钮随之向上移动。
- 自定义 Tab 点击后直接调用 `wx.switchTab`，没有先结束待办输入框的键盘状态；待办输入框开启了 `adjust-position`，页面隐藏时仅处理草稿保存。

本次底栏改用 `screenHeight - safeArea.bottom` 的设备安全区像素值，组件挂载、页面显示和尺寸变化时重测，不用受键盘影响的 `windowHeight` 计算留白，也不再依赖底栏 CSS 的安全区环境值。缺失或非法测量值回退为 0。切换前调用 `wx.hideKeyboard`，在完成回调内切 Tab；重复点击会被抑制，切换失败后允许重试。完成回调的自动化检查不代表已验证真机键盘动画结束时间。

保留五套主题、底栏触控尺寸和待办草稿原有保存逻辑。修复覆盖了上述代码风险，截图问题仍需反馈设备验证。

## 删除当前周这一次课，却删除了其他教学周

用户确认预期是“只删除当前第 N 周这一次课”。现有一条 `Course` 记录代表一个星期几／连续节次，`weeks` 保存这一时段的全部教学周；原编辑页的单时段删除调用 `remove(id)`，按 ID 删除整条记录，完全没有使用已经传入的 `sourceWeek`。因此即使选择单时段，其他教学周也会消失。多时段课程还会重新弹出删除范围菜单，与进入编辑页时的选择不一致。

新增 `removeCourseOccurrence(id, week)`，读取并校验最新存储后：

1. 确认该教学周有效且目标时段确实有课；非法、过期或重复删除请求不写入。
2. 仅从目标时段的 `weeks` 移除这一周，剩余周次以 `custom` 保存，避免重新展开“全部周／单双周”时补回已删除的课。
3. 如果没有剩余周次，才删除该条记录。
4. 多时段课程的目标时段沿用现有编辑拆分规则，分配独立课程组，满足 V5 同组必须共享周次的约束。其他时段和其他课程逐字段保留。拆分后的时段后续按独立课程组编辑，其主题课程色可能随新组 ID 改变。
5. 使用既有写入、回读校验和失败回滚事务，不升级课表 V5、待办 V3 或备份格式。

单时段编辑页显示“删除第 N 周本次课”，确认框解释会保留其他周和其他时段；整门编辑页显示“删除整门课程”，确认框明确全部教学周和时段数量。删除不再二次选择范围。

本次修改仅调整删除语义；保存课程时原有周次编辑规则继续生效。
