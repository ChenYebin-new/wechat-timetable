# 数据版本兼容说明

本次整理保留现有格式和兼容行为，不增加数据版本，不改变页面操作。各业务数据域独立演进，版本数字无需相同。当前格式保存在各自的单一键中；最近备份是额外恢复快照，并非每个历史版本各存一份。

## 版本与模块职责

| 数据域 | 当前版本 | 历史兼容 | Storage 键 |
| --- | --- | --- | --- |
| 课表 | V5 | V1–V4 | `timetable_courses` |
| 待办与随想 | V3 | V1、V2 | `timetable_todos` |
| 课表备份封装 | V1 | 内部 data 可为课表 V1–V5 | 最近备份 `timetable_recent_backup` |
| 待办与随想备份封装 | V1 | 内部 data 必须为待办 V3 | 最近备份 `timetable_todos_recent_backup` |

以下路径均相对于 `wechat-timetable/miniprogram/`：

| 模块 | 职责 |
| --- | --- |
| `constants/data-versions.ts` | 独立的 `TIMETABLE_SCHEMA_VERSION`、`TODO_SCHEMA_VERSION`、`TIMETABLE_BACKUP_VERSION`、`TODO_BACKUP_VERSION` 与课表版本集合。原有常量导入路径保留兼容导出。 |
| `models/course.ts` | 当前业务模型和中性的 `CourseFields`；当前课程不继承历史版本接口。 |
| `models/course-legacy.ts` | 课表 V1–V4 和兼容联合类型；原类型导入路径保留 type-only 导出。 |
| `services/timetable-compat.ts` | `decodeStoredTimetable` 与 `decodeBackupTimetable` 两个纯入口，分别保留本地读取和导入规则，不访问 wx 或 Storage。前者返回读取状态与可选迁移候选，后者返回规范化数据或原有错误。 |
| `services/storage-codec.ts` | 当前 V5 的严格快照校验及原有显式读取状态。 |
| `utils/course-data-rules.ts` | 颜色、周次、重复 ID、课程组共同信息和首个课程冲突的公共规则；错误文案及检查顺序由调用入口保留。 |
| `services/course-storage.ts`、`services/backup-service.ts` | 页面公开服务、Storage 读取、备份、迁移落盘、回读校验及回滚；事务仍由原服务执行。 |
| `services/todo-storage.ts`、`services/todo-backup-service.ts` | 保留待办 V3 严格解码、显式迁移与备份事务。本轮只整理其版本常量引用，不抽象成通用迁移框架。 |

V4 作息推断继续由现有 `utils/period-settings.ts` 的纯函数完成，经兼容入口调用。当前格式校验和备份解析仍保持职责分离；备份服务先校验外层封装，纯兼容入口处理内部数据。

## 兼容矩阵

下表的“接受”均以字段合法为前提，不表示损坏数据会被自动修复。历史数据在本地和备份入口之间的差异是既有行为，本次不扩大或收紧接受范围。

| 输入 | 本地读取与迁移 | 备份导入 |
| --- | --- | --- |
| 课表 V1 | 读取旧课程，暂不写入；设置有效学期后备份并升级为 V5 | 预览提示补充学期；导入时展开全部周并补课程组、默认作息 |
| 课表 V2 | 读取时先备份，再补 `groupId = id` 与默认作息并安全升级 V5 | 同样补课程组和默认作息 |
| 课表 V3 | 读取时备份并补默认作息，安全升级 V5 | 保留课程组并补默认作息 |
| 课表 V4 | 读取时备份并推断第一节起点、午休锚点和单节时长，安全升级 V5 | 使用相同作息推断，保持原有起止时间 |
| 课表 V5 | 严格校验，通过后原样读取 | 先严格校验完整快照，再按原有导入规则整理文本；不重复执行课程组、ID、周次和冲突检查 |
| 课表 V2–V4 的 `all + []` | 作为旧版“全部周”表示法展开 | 同样展开；当前 V5 不接受这种空数组表示法 |
| 课表 V2–V5 空数据、`term: null` | 合法空课表；V2–V4 保持原自动迁移 | 可导入，无课程时不强制设置学期 |
| 待办 V1、V2 | 读取不写；待办页沿用显式 V3 安全迁移，保留 `legacyTiming` 等历史信息 | 待办备份页阻止操作，提示先进入待办完成迁移 |
| 待办 V3 | 严格校验并读取 | 只接受待办专属封装及完整 V3 数据，原文空白和换行不变 |
| 无存储 | 按对应域的空数据读取 | 导出/恢复保持原服务规则 |
| 未知版本、损坏数据、读取失败 | 按原状态停止写入，保留原数据 | 非法备份拒绝；本机异常时保持原服务的写入保护 |

需要特别保留的入口差异：

- 本地课表读取保留名称、教师和教室的原始空白。课表备份导入会 trim 这些文本，空白教师/教室字段被省略；待办随想不采用课表的文本整理。
- 本地旧课表严格检查根对象、课程、学期和 V4 作息的允许字段；旧备份入口对部分附加字段沿用原有宽容策略。V5 两个入口都先严格校验，不允许用历史规则绕过当前快照校验。
- 本地旧数据最终迁移候选还需通过 V5 严格校验；旧备份导入保留原错误顺序与文案。公共函数只共享相同判断，不统一不同入口的错误提示。
- `Course.weeks` 在当前持久化格式中为非空规范数组；V1 尚未补学期的读取视图仍可能暂用空数组。TypeScript 历史类型本身不会额外占用 Storage。

## 回归基线与验收

先将待办备份功能固定为本地提交 `ba5ca59`，再建立 `codex/refactor-data-version-compat`。该提交是本次兼容比较的原实现基线，不表示已合并或发布。

`tests/helpers/version-compat-matrix.mjs` 定义 92 个确定性合成样本，覆盖课表 V1–V5、待办 V1–V3、空数据、未知版本、损坏字段、空白、未知字段、重复 ID、课程冲突、课程组不一致、周次数组及 V4 作息。`tests/fixtures/version-compat-baseline.json` 在重构前生成，固定每个样本的状态、是否接受与完整结果的 SHA-256。摘要包含服务输出、迁移/覆盖结果、按顺序记录的写入键以及最终 Storage，固定时间避免备份时间戳扰动；另一业务键必须保持不变。重构时不得重新生成摘要来消除失败。

执行 `npm run check`，除上述矩阵外继续运行已有故障注入测试，包括迁移备份失败、静默写入失败、回读不一致、目标写入失败和回滚失败。新增直接调用纯解码的测试禁止任何 wx 访问、冻结输入，并显式核对 V4 午休锚点与单节时长。

运行时验收使用独立临时项目与合成数据，核对旧课表读取升级、V1 补学期导入、V4 旧备份导入、V5 剪贴板往返和待办迁移。自动化确认弹窗响应、模拟器页面重建、真机冷启动分别记录，不互相替代。具体完成情况见[开发与上线指南](./微信课表小程序开发与上线指南.md)的本次验证记录。
