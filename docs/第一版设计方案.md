# 微信课表小程序 第一版设计方案

> 适用项目：微信课表小程序（第一版）
> 开发负责人：Liu　·　需求审核/发布：Yebin
> 文档性质：开发前评审用；评审通过后作为实现依据

## 1. 总体架构

原生微信小程序 + TypeScript，使用 WXML/WXSS。不引入跨端框架、UI 组件库、云开发、后端服务。

整体分层：**页面**、**组件**、**模型**、**服务**、**工具**。

```
miniprogram/
├─ app.json / app.ts / app.wxss        # 页面注册、全局标题、全局主题样式
├─ models/course.ts                    # 课程与存储根的数据类型
├─ constants/timetable.ts              # 星期名、9 节课时、颜色板、存储 key
├─ services/course-storage.ts          # 统一读写本地 Storage
├─ utils/course-validator.ts           # 必填、范围、冲突校验
├─ utils/timetable-layout.ts           # 由课程数据计算卡片定位（flex + 绝对定位）
├─ components/timetable-grid/          # 七天课表网格组件（课程卡片内联渲染于此）
└─ pages/
   ├─ timetable/index.*                # 课表主页
   └─ course-edit/index.*              # 新增 / 编辑课程页
```

## 2. 数据模型

### 课程 `Course`

```ts
interface Course {
  id: string;          // 唯一主键，如 `${Date.now()}-${随机后缀}`
  name: string;        // 课程名称（必填）
  day: number;         // 1=周一 … 7=周日
  startPeriod: number; // 开始节次，1..9
  endPeriod: number;   // 结束节次，1..9
  teacher?: string;    // 教师（可选）
  location?: string;   // 教室（可选）
  color: string;       // 主题色，取自预设色板
  createdAt: number;   // 创建时间戳
  updatedAt: number;   // 更新时间戳
}
```

### 存储根

使用**一个 key 存整个对象**，便于将来通过 `schemaVersion` 做结构迁移。

```ts
interface TimetableStorage {
  schemaVersion: 1;
  courses: Course[];
}
```

- 存储 key 固定为 `timetable_courses`。
- `schemaVersion` 为将来新增学期、教学周、单双周等规则预留迁移入口。

## 3. 常量

- `DAYS = ['周一','周二','周三','周四','周五','周六','周日']`（从 1 起索引）
- `PERIODS`：9 项，格式 `{ index, label, time, start, end }`，时间严格采用第一版固定课时：

| 节次 | 时间 |
| --- | --- |
| 第 1 节 | 08:00–08:50 |
| 第 2 节 | 09:00–09:50 |
| 第 3 节 | 10:00–10:50 |
| 第 4 节 | 11:00–11:50 |
| 第 5 节 | 14:00–14:50 |
| 第 6 节 | 15:00–15:50 |
| 第 7 节 | 16:00–16:50 |
| 第 8 节 | 17:00–17:50 |
| 第 9 节 | 18:00–18:50 |

- `COLOR_PALETTE`：蓝绿色系为主的若干 hex 色值（如 `#0ea5a4`、`#10b981`、`#22c55e`、`#06b6d4`、`#3b82f6` 等）。
- `MAX_PERIOD = 9`。

## 4. 服务层（course-storage）

对外只暴露四个方法，**页面不直接操作 Storage**：

- `getCourses(): Course[]` —— 读取全部课程；首次启动、无数据或数据异常时返回 `[]` 并完成初始化，不白屏不崩溃。
- `getCourseById(id): Course | undefined`
- `save(course): void` —— 有 `id` 则更新，无 `id` 则新增；统一写入 `createdAt / updatedAt`。
- `remove(id): void`

内部通过 `_load()` / `_persist(data)` 统一处理根对象的读取与写回，并补齐 `schemaVersion`。

## 5. 校验与冲突

`validate(course, all, excludeId?)` 返回 `{ ok, errors: string[] }`，校验规则：

1. 课程名称不能为空。
2. `day` 在 1..7。
3. `startPeriod` 与 `endPeriod` 均在 1..9。
4. `startPeriod <= endPeriod`。
5. **冲突检测**：与 `all` 中除 `excludeId`（编辑时排除课程自身）以外的课程比较，凡 `day` 相同、且节次区间重叠即冲突。重叠判定：

   ```ts
   const overlap = !(a.endPeriod < b.startPeriod || a.startPeriod > b.endPeriod)
   ```

   示例：第 2–4 节与第 4–5 节冲突；第 2–3 节与第 4–5 节不冲突。
6. 冲突提示需明确指出"周几 + 哪些节次 + 冲突课程名"，例如：`周四 第4–5节 与「线性代数」冲突`。

> 由于同一天节次重叠被禁止，因此一天内课程不会互相重叠，网格摆放可以按"列=星期、行=开始节次、跨行=连续节次数"直接定位，无需再做同一天的水平分组。

## 6. 课表网格布局

使用 **flex 列 + 绝对定位**（不使用 CSS Grid，以避免部分 iOS 设备的渲染兼容问题），无需横向滚动即可查看七天。

- 结构：`表头行(星期名)` + `主体行`；主体行 = `时间栏(固定宽度)` + `7 列星期(等宽 flex:1)`。
- 每天一列高度 = 9 × 单个节次高度（`CELL_HEIGHT = 124rpx`）；时间栏与每一天列共用同一节次高度。
- 每张卡片使用绝对定位，并在节次单元内保留 `4rpx` 的上下间距：`top = (startPeriod - 1) × CELL_HEIGHT + 4`，`height = (endPeriod - startPeriod + 1) × CELL_HEIGHT - 8`。

  例如：周一第 2–4 节 → `top = 128rpx; height = 364rpx`。

- 时间栏逐行显示 `第N节` 与起止时间（`start` / `end`）。
- 单节课高度 = 1 个节次；连续多节课合并为一张**跨行卡片**（高度按跨的节次数累加）。
- 长课程名使用 `-webkit-line-clamp`（最多两行）+ 省略，完整内容在编辑页显示。
- 卡片文字颜色依据背景亮度自动选择深色/白色，保证可读性。
- 空课表时显示新增课程引导。

## 7. 页面

### 课表主页 `pages/timetable`

- `onShow` 中调用 `getCourses()` 重新渲染，保证新增/编辑/删除后返回即显示最新结果。
- 顶部：页面标题 + `新增课程` 按钮。
- 中部：`<timetable-grid day-slots="{{daySlots}}" bind:cardtap="onCourseTap" />`。
- 点击空白引导按钮 → 跳转编辑页（新增模式）。
- 点击课程卡片 → 跳转编辑页（带课程 `id`，编辑模式）。

### 课程编辑页 `pages/course-edit`

- 表单字段：名称(必填)、星期(picker，仅显示“周一”至“周日”)、开始节次(picker)、结束节次(picker)、教师(选)、教室(选)、颜色(色板选择)。
- 新增：字段为空表单；编辑：通过 `getCourseById(id)` 预填。
- 保存：先 `validate()`，通过后 `save()` 并 `wx.navigateBack()`；失败则用 `wx.showModal` 展示完整错误信息。
- 删除：`wx.showModal` 二次确认后 `remove()` 并返回。
- 保存、编辑、删除后返回主页，主页即时刷新。

- 蓝绿主色系（如 `#0ea5a4`），全局背景浅灰。
- 圆角卡片（约 `12rpx`）、轻量半透明层。

- 窄屏不挤压；输入时键盘不遮挡主要表单。
