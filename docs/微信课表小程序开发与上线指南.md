# 微信课表小程序开发与上线指南

> 适用项目：第一版微信课表小程序
> 文档整理日期：2026-09-05
> 第一版范围：七天周课表、手动新增/编辑/删除课程、本地保存
> 暂不包含：待办事项、文件导入、教务系统导入、账号登录、云同步、消息提醒

## 1. 总体流程

微信小程序的开发和上线主要涉及两个平台：

- **微信开发者工具**：创建或导入项目、编译、模拟器预览、真机调试、上传代码。
- **微信公众平台后台**：注册小程序、获取 AppID、配置基本信息和服务类目、备案、提交审核、正式发布。

完整流程如下：

```text
注册微信小程序账号
    ↓
取得正式 AppID
    ↓
填写名称、头像、介绍和服务类目
    ↓
提交小程序备案
    ↓
安装微信开发者工具
    ↓
创建或导入 TypeScript 项目
    ↓
开发课表页面和课程编辑页面
    ↓
模拟器预览和真机测试
    ↓
上传开发版本
    ↓
设置体验版并测试
    ↓
提交微信审核
    ↓
审核通过后正式发布
```

注意：**在微信开发者工具中“上传代码”不等于正式上线。** 上传后还需要在微信公众平台提交审核，审核通过后再点击发布。

## 2. 第一版采用的技术路线

| 层级 | 选择 |
| --- | --- |
| 开发框架 | 原生微信小程序 |
| 编程语言 | TypeScript |
| 页面结构 | WXML |
| 页面样式 | WXSS |
| 开发与预览 | 微信开发者工具 |
| 主要代码编辑器 | PyCharm |
| 数据保存 | 微信本地 Storage |
| 后端服务 | 不使用 |
| 云开发 | 暂不接入 |
| UI 组件库 | 暂不引入 |

第一版本地运行，不需要购买服务器、配置域名或建立用户账号系统。

### 第一版必须实现

- 周一至周日七列课表。
- 左侧节次和上课时间。
- 连续多节课程显示为一张跨行课程卡片。
- 手动新增课程。
- 点击课程进行编辑。
- 删除课程。
- 检查同一天、同一节次的课程冲突。
- 关闭后重新进入，课程数据仍然存在。
- 空课表状态和新增课程引导。

### 第一版暂不实现

- 待办事项。
- CSV、Excel、图片和教务系统导入。
- 复制和粘贴整张课表。
- 学期、教学周、单双周、调课、停课。
- 用户登录和多设备同步。
- 微信订阅消息和上课提醒。
- 心情、打卡、工具箱等附加功能。
- 用户上传自定义背景照片。

第一版中的课程默认每周重复。后续再通过数据升级增加学期、教学周和单双周规则。

## 3. 注册微信小程序账号

1. 打开[微信公众平台](https://mp.weixin.qq.com/)。
2. 选择注册“小程序”。
3. 根据页面提示选择主体类型并完成身份核验。
4. 绑定管理员微信。
5. 填写小程序名称、头像和介绍。
6. 选择与实际课表功能一致的服务类目。

第一版仅提供个人课表工具，不涉及收费、学校官方服务、直播或课程销售，一般可以从个人主体路线开始。最终可选类目和材料要求以注册时微信公众平台实际显示为准。

服务类目应优先检查与日历、日程或实用工具接近的选项，不能为了通过审核选择与真实功能不符的类目。

## 4. 获取并保管 AppID

注册完成后，登录微信公众平台，在“开发管理”或“开发设置”中找到：

```text
AppID（小程序 ID）
```

AppID 用于把本地项目与正式小程序账号关联。

注意事项：

- AppID 可以写入项目的 `project.config.json`。
- `AppSecret` 不用于第一版本地课表。
- 不要把 AppSecret 写进小程序前端代码。
- 不要把 AppSecret 提交到 Git 仓库或发送给不可信第三方。

## 5. 完成小程序备案

新增微信小程序需要完成备案后才能正式上架。建议注册完成后尽早开始备案，不要等代码全部写完。

登录微信公众平台后，根据后台当前入口进入：

```text
首页 → 去备案
```

或者：

```text
设置 → 小程序备案
```

根据页面提示填写和准备：

- 主体身份信息。
- 小程序负责人信息。
- 联系方式。
- 小程序名称和服务内容。
- 身份或人脸核验。
- 短信核验。
- 平台要求的其他资料。

备案和代码审核是两件不同的事：

- **备案**：确认由谁提供这个互联网服务。
- **代码审核**：检查当前版本的功能和内容是否符合微信平台规则。

参考：[微信小程序备案操作指引](https://developers.weixin.qq.com/miniprogram/product/record_guidelines.html)

## 6. 安装微信开发者工具

从以下官方页面下载 Windows 稳定版：

- [微信开发者工具官方下载](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)

安装后：

1. 打开微信开发者工具。
2. 使用管理员或已经添加为开发者的微信扫码登录。
3. 进入项目管理页面。
4. 根据项目状态选择“新建项目”或“导入项目”。

## 7. 创建或导入项目

### 情况 A：微信开发者工具生成初始项目

选择“新建小程序项目”，填写：

- 项目名称：可先使用“我的课表”等工作名称。
- 项目目录：`C:\Users\Yebin\Desktop\VibeWork\WechatCode`。
- AppID：填写正式小程序 AppID。
- 开发模式：小程序。
- 语言或模板：TypeScript。
- 后端服务：不使用云服务。

### 情况 B：项目代码已经建立

如果项目文件已经由开发工作生成：

1. 在微信开发者工具中选择“导入项目”。
2. 选择 `C:\Users\Yebin\Desktop\VibeWork\WechatCode\wechat-timetable`。
3. 填写或确认正式 AppID。
4. 确认开发模式为“小程序”。
5. 导入后点击“编译”。

不要在已有代码的目录中重新生成一套模板，以免出现重复文件或覆盖现有配置。

## 8. 推荐项目结构

```text
WechatCode/
├─ wechat-timetable/
│  ├─ miniprogram/
│  │  ├─ app.ts
│  │  ├─ app.json
│  │  ├─ app.wxss
│  │  ├─ pages/
│  │  │  ├─ timetable/       # 课表主页
│  │  │  └─ course-edit/     # 新增和编辑课程
│  │  ├─ components/
│  │  │  ├─ timetable-grid/  # 七天课表网格
│  │  │  └─ course-card/     # 课程卡片
│  │  ├─ models/             # 课程和节次数据类型
│  │  ├─ services/           # 本地数据读取和保存
│  │  ├─ utils/              # 布局计算和课程校验
│  │  └─ assets/             # 项目自有图片资源
│  ├─ project.config.json
│  ├─ tsconfig.json
│  └─ package.json
├─ README.md
├─ CHANGELOG.md
└─ .gitignore
```

主要模块职责：

- `timetable-layout`：根据星期、开始节次和结束节次计算课程卡片的位置与高度。
- `course-validator`：校验课程名称、节次范围和时间冲突。
- `course-storage`：统一读取、新增、修改和删除本地课程数据。

## 9. 日常开发操作

推荐配合方式：

1. 使用 PyCharm 编辑 TypeScript、WXML 和 WXSS 文件。
2. 保持微信开发者工具打开。
3. 修改代码后，在开发者工具中重新编译或使用自动编译。
4. 使用模拟器快速检查布局和交互。
5. 查看 Console 和调试器中的错误。
6. 页面基本完成后，使用手机扫码预览。
7. 正式上传前进行真机调试。

## 10. 模拟器、预览和真机调试

### 10.1 模拟器编译

在微信开发者工具中点击“编译”，检查：

- 页面能否正常打开。
- 周一至周日是否完整显示。
- 节次和时间是否对齐。
- 课程卡片是否正确跨节。
- 新增、编辑和删除是否有效。
- Console 是否存在错误。

### 10.2 手机预览

点击“预览”生成二维码，用已绑定权限的微信扫码。

在手机上重点检查：

- 字体是否过小。
- 七天布局是否过度拥挤。
- 刘海、灵动岛和顶部安全区域是否遮挡内容。
- 输入课程时，键盘是否遮挡表单。
- 页面滚动是否顺畅。
- 关闭后再次打开，课程是否仍然存在。

### 10.3 真机调试

使用“真机调试”查看手机实际运行时的日志和错误。

最低测试范围：

- 一台 iPhone。
- 一台 Android 手机。
- 窄屏手机。
- 空课表。
- 课程较多的课表。
- 周日课程。
- 连续多节课程。
- 两门课程时间冲突。
- 编辑和删除后重新打开小程序。

## 11. 成员和体验权限

如果只有一个人开发，管理员扫码登录开发者工具即可。

如果需要其他人参与或测试：

1. 登录微信公众平台。
2. 打开成员管理。
3. 添加项目成员或体验成员。
4. 给项目成员分配必要权限。
5. 让体验成员通过体验版二维码测试。

给其他人测试时，应使用体验版，不要为了测试提前发布线上版本。

## 12. 上传开发版本

开发和真机测试通过后，在微信开发者工具右上角点击“上传”。

填写：

- 版本号，例如 `0.1.0`。
- 项目备注，例如“首个课表页面，支持手动添加、编辑和删除课程”。

上传完成后，代码只会进入微信公众平台的“开发版本”，不会直接公开上线。

## 13. 设置体验版

登录微信公众平台，进入：

```text
开发管理 → 版本管理 → 开发版本
```

找到刚上传的版本，将其设置为体验版，再进行最后一轮测试。

体验版测试清单：

- 新用户能看懂如何添加第一门课程。
- 所有可见按钮都能正常使用。
- 没有半成品入口。
- 没有测试文字、演示账号或调试信息。
- 没有复制其他小程序的名称、Logo、背景图片或品牌元素。
- 没有申请与当前功能无关的权限。
- iOS 和 Android 均能正常显示。

## 14. 提交微信审核

体验版验证完成后，在版本管理中选择“提交审核”。

通常需要填写：

- 服务类目。
- 主要功能说明。
- 需要审核的功能页面。
- 页面路径。
- 测试说明。
- 如果存在登录，提供审核测试账号。

第一版没有登录，因此不需要提供测试账号。

功能说明可以参考：

> 本小程序提供个人课程表管理功能。用户可以手动添加课程名称、星期、节次、教室和教师信息，并在周课表中查看、修改或删除课程。课程数据仅保存在用户本地。

页面路径示例：

```text
pages/timetable/index
pages/course-edit/index
```

实际填写时必须以最终 `app.json` 中注册的页面路径为准。

审核时间不固定，以微信公众平台后台和审核通知为准。

## 15. 审核通过后正式发布

审核通过后，管理员进入微信公众平台，在版本管理中找到审核通过的版本，点击“发布”。

根据后台提供的选项选择全量发布或灰度发布。第一版用户规模较小时，通常可以使用全量发布。

发布成功后，用户可以通过以下方式进入：

- 小程序码。
- 好友分享。
- 小程序名称搜索。
- 微信最近使用记录。

搜索展示还取决于小程序名称、搜索可见设置和微信平台规则。发布后应先使用正式小程序码进行一次真实访问验证。

## 16. 审核常见问题

课表小程序第一版要重点避免：

- 服务类目与实际功能不一致。
- 页面只有展示效果，没有可操作功能。
- 添加、编辑或删除按钮无法使用。
- 使用参考小程序的名称、Logo、照片或其他受保护素材。
- 隐私说明与真实数据处理方式不一致。
- 申请相册、位置、用户资料等非必要权限。
- 显示待办、云同步等尚未完成的入口。
- 模拟器正常但真机出现白屏、遮挡或文字不可读。
- 审核说明没有告诉审核人员如何添加和查看课程。

第一版完全使用本地数据，原则上不需要申请敏感权限。

## 17. 版本更新流程

以后每次更新都重复以下流程：

```text
修改代码
  ↓
模拟器与真机测试
  ↓
上传新版本号
  ↓
设置体验版验证
  ↓
提交审核
  ↓
审核通过后发布
```

建议采用递增版本号：

```text
0.1.0  第一版课表
0.1.1  小问题修复
0.2.0  增加教学周和单双周
0.3.0  增加课表备份与恢复
1.0.0  功能和稳定性达到正式版本标准
```

4. 安装微信开发者工具稳定版。
