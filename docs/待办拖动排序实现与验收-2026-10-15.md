# 待办拖动排序实现与验收（2026-10-15）

## 使用规则

- 在同一天的目标列表中长按正文，再上下拖动，松手保存顺序。未完成目标始终在前、已完成目标在后，只在各自组内排序，不跨日期或改变完成状态。
- 普通上下滑动继续滚动页面，轻点正文编辑、点击圆圈勾选和更多菜单的编辑／删除保持原入口。编辑器打开或随想仍聚焦时不启动拖动；同组仅一条时无需排序。
- 长按后卡片放大约 4%、上抬 8px，出现分层阴影；拖动保持跟手，同组其他卡片平滑让位，虚线标出插入空位，行高按实际标题与备注测量。松手后约 220ms 完成缩回和落位。长列表拖到上下边缘时滚动页面，回到中间即停止。更多菜单提供上移／下移，不要求必须使用长按手势。
- 取消、离开页面、切日、展开／收起月历、窗口尺寸变化、多指触摸或系统中断时撤销本次拖动。原序不变，不以拖动后的松手误触编辑或勾选。
- 松手后保存一次，未移动时不写入。保存失败恢复原序并说明原因；若列表在拖动期间发生新增、删除、完成状态或排序变化，拒绝用陈旧列表覆盖。
- 重新进入页面、重建页面，以及待办与随想备份恢复后保留顺序。新增目标排在当日未完成组末尾；编辑保留位置，完成／恢复时保留存储位置，其余目标的相对顺序不变。

## 数据与交互实现

`timetable_todos` 继续使用 schema V3，独立备份继续使用 `kind: todo-journal`、`backupVersion: 1`。使用现有 `items` 数组排列表示顺序，没有新增排序字段或 Storage 键，也不改写创建／完成时间。页面按日期过滤后稳定分区为未完成和已完成，不再按创建时间覆盖手动顺序。旧客户端可能仍以创建时间显示，导出格式本身保持兼容。

`services/todo-storage.ts` 的 `reorderTodos` 每次读取并校验最新存储，核对完整的同日同状态 ID 序列，再仅替换这些条目所在的数组位置，保留其他记录。复用写入、回读验证及失败回滚事务；备份无需增加特殊处理，导出和恢复均保留数组排列。

`pages/todo/drag.wxs` 在渲染层处理手势与跟手位移。普通滑动不拦截默认滚动，长按成功后才拦截移动；拖动后的点击被抑制，新的轻点恢复原编辑操作。逻辑层只负责实际行高测量、插入位置、边缘滚动与松手保存。迟到的测量、旧手势事件和备份恢复后的旧回调均有失效保护。

保留五套主题和既有按钮尺寸。行的跟手位移由 WXS 直接设置，不给拖动位置增加过渡延迟；独立的 `todo-surface` 负责缩放、抬升和阴影，相邻行使用位移过渡。插槽使用伪元素，避免改变纸上与秩序主题的 first／last-child 分隔线规则。纸上主题仅在拖动和落位时解除列表裁切，减少动态效果设置下关闭缩放和过渡，仍保留阴影与插入位置反馈。

落位前先保存排序，在原 DOM 里把卡片移到插入位置，结束后再合并更新数组顺序与位移清零，避免跳回原处。下一次轻点编辑、勾选、更多菜单或添加目标可立即结束落位并继续原操作；离页会清除动画计时器，已经松手保存的顺序不会回退。

模拟器交互检查另发现并修正了实际渲染层问题：属性观察绑定改用 `draglayout`，避免带连字符的自定义属性没有触发观察；首次浮起状态与有效拖动布局在同一次更新中发送，避免空闲值中断手势。模拟器给出全零的触摸结束坐标时沿用最后移动点，避免松手后错误回到起点。
