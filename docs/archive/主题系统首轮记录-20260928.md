## 原生模拟器

工具：本地微信开发者工具、miniprogram-automator 0.12.1、基础库 3.17.2；先在 iPhone 15 Pro Max **430px** 逻辑宽度检查，重开项目后另取得 **390px** 完整流程截图。

- C／E 均走查全部 11 个页面、待办月历展开、课表多选和时段重选。
- 实际应用主题后返回已有页面，目标草稿、课程草稿、待办选日、月历浏览月份保持；从设置返回保持所选第 4 周。仅点选预览时主题不变。
- 额外注入随想保存失败，再实际应用另一主题并返回待办：未保存正文、失败状态、所选日期及月历月份均保留，真实 Storage 比较一致。故障注入结束后重开项目，清除会话内的错误状态。
- 1、9、14 节分别核对组件行数；七列均与节次数一致。检查跨节卡片、同组不同日期的同色显示、14 节底部滚动、单节长中文名称省略，以及多选反馈。
- 检查空课表、读取错误提示、禁用按钮、随想保存中／失败状态、表单及备份长页底部。状态图通过临时展示字段注入，不触发真实业务保存。
- 月历 42 格；原生测量日期格与切周箭头的触控尺寸满足 44px 下限。
- 导航和原生 Tab 的颜色与图标随主题更新。校园首页使用较大插画，表单和设置子页使用较小装饰。
- 完整流程与边界检查均隔离真实 Storage：合成课程／待办通过 mock API 提供，偏好写入也只进入内存。检查结束恢复 mock 和原活跃主题，对实际全部 Storage 键及值逐项比较一致；未向真实课程或待办写入演示记录。

首次脚本返回的数组跨执行环境，导致合成课表节次与课程数在组件中显示异常。读取 mock 改为 JSON 复制后复核，组件正确显示 1／9／14 节；真实存储读取也独立确认正常。过程中热更新曾中断 mock，长时间运行后模拟器的单节编辑事件通道也曾失效；关闭并重新打开当前项目后，真实存储下的正常点击流程恢复。上述为测试环境问题，不以失败截图作为最终视觉证据。

原生截图和报告仅保存在本机忽略目录 `dist/appearance-native/`；完整流程为 `report.json`，边界与 Storage 比对为 `bounds-report.json`，失败随想保留为 `journal-report.json`，`index.html` 可对比两套外观。对应测试脚本为 `dist/verify-appearance.cjs`、`dist/verify-appearance-bounds.cjs` 和 `dist/verify-appearance-journal.cjs`。页面展示数据均为合成示例。
