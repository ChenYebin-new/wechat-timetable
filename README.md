# 微信课表小程序

一个使用原生微信小程序和 TypeScript 开发的个人课表与待办工具。

当前外观：默认 A「纸上拾课」，可在“设置 → 外观”切换 B「秩序之间」、C「奶油积木」、E「校园晴日」和 F「像素课间」。已保存的有效外观偏好继续保留；无偏好或偏好异常时使用 A。五套外观具有独立的排版、材质、控件和图标细节，覆盖全部页面与共用组件；课程颜色自动随主题调整，取消手动选色。课程块统一采用浅色底、左侧彩色竖线和左对齐文字，保留各主题的纸纹、圆角或像素端点；课表、时段选择与外观预览共用相同配色规则。新视觉规范见 [DESIGN.md](DESIGN.md)，验证边界见 [主题系统验收记录](docs/主题系统验收记录.md)。

已实现：基于原生微信小程序 + TypeScript 的七天周课表与本地待办，支持课程新增、编辑、删除、冲突检查、数据备份与恢复（V1.0.1）、学期与教学周（V1.1）、左右滑动切周、课表网格长按多选新增、全局课程时间设置，以及按日目标与每日随想。课表与待办数据分别保存在微信本地 Storage。

## 第一版功能（已实现）

- 展示周一至周日七列课表，左侧按全局作息显示 1–14 节课程及对应时间。
- 课表主页采用主题页头、周次工具栏与一周课表，七天保持同屏显示。A 为纸感手账，B 突出大号周次和严格分隔，C 为奶油圆角，E 为校园插画，F 为像素校园与阶梯描边；自定义导航与双 Tab 保留微信胶囊和系统安全区。
- 连续多节课程显示为一张跨行课程卡片。
- 手动新增、编辑和删除课程（删除前二次确认）。
- 检查同一天、同一节次的课程冲突，编辑时排除课程自身。
- 使用微信本地 Storage 保存课程，关闭重进后数据仍在。
- 所有页面都支持通过微信右上角菜单发送给好友和分享到朋友圈：好友卡片直接进入课表首页；朋友圈受微信路径限制，先展示统一品牌预览，点击系统“前往小程序”后进入课表首页。分享参数不携带本机课程、待办或编辑数据。
- 空课表时展示新增课程引导。
- 数据管理（V1.0.1）：导出课表为 JSON 文本、粘贴并校验导入、覆盖或按课程组原子合并、恢复最近自动备份。
- 学期与教学周（V1.1）：设置第一教学周星期一与学期总周数（1–30）；课表顶部显示当前"第 N 周"，支持左右滑动课表、上一周/下一周按钮和直接选周；课表只显示所选周实际有课的课程。进入长按多选后会暂时锁定切周，避免误选到其他周。
- 第一教学周日期选择：学期设置与旧版课表导入共用“年份 / 月份 / 星期一”滚轮，日期列只显示所选月份的星期一，页面明确标注“周一”。滚动不改变页面日期，确定后更新，取消保持原值；年份默认覆盖 1900–2100 年，并自动覆盖当前年份和已有学期日期。学期数据格式与原有保存、备份和迁移流程保持兼容。
- 课程周次（V1.1）：每门课程可选全部周、单周、双周或指定周次。
- 冲突判断（V1.1 升级）：星期、节次、周次三者都重叠才算冲突。
- 支持长按课表空白格 1.2 秒进入多选，可跨星期选择多个时段；同一天连续节次自动合并，并作为同一门课程统一填写信息。
- 点击课程时每次都会重新询问编辑范围；多时段课程支持整体编辑、重新选择时段，或仅编辑当前时段并自动拆分。删除时可选择仅删除当前时段或整门课程。
- 课表主页提供统一“设置”入口，可进入学期设置、课程时间设置和数据管理；原周次栏中的“学期”快捷入口继续保留。
- “设置 → 关于我们”展示反馈邮箱和开发者微信二维码原图；支持复制邮箱、长按选择邮箱文字和点击放大二维码，并提供问题反馈建议。
- 课程时间设置支持全局课时时长、课间休息、每日课程数和逐节起止时间。修改全局规则会立即重排下方课程；手动开始时间作为午休等固定锚点保留，手动结束时间作为该节专属时长保留，发生锚点冲突时不会覆盖原设置。
- 底部提供“课表 / 待办”双入口；待办顶部点击日期直接选择某一天，也可通过左右箭头切日或回到今天。所选日期显示“今日目标 / 当日目标”和完成数，目标在当前页添加、编辑、删除和完成/恢复，备注按需展开；不再设置执行时间、截止日期或跨日期状态筛选。
- 待办页提供默认收起的小月历：点击“展开月历”定位所选日所在月，按周日起始展示七列六行；邻月日期也可选，有目标的日期显示单个圆点，今天描边、选中日使用当前主题的操作色。翻月只浏览，选日才切换目标与随想，成功后保持展开；保存失败或取消放弃编辑不会改变选日与高亮。月历展开时始终可返回今天，浏览状态不另存 Storage。
- 未完成目标在所属日期的次日本地自然日开始时显示“已过期”，不会删除、自动顺延或混入今天。历史目标允许补写、编辑和补记完成；前后台跨日会重新计算状态，输入草稿仍属于打开时的原日期。
- 每天有一篇独立随想，最多 2,000 字符，保留原文与换行。停止输入 500 毫秒后自动保存，失焦、切日和离开页面前立即保存；失败显示未保存及重试，保留当前会话草稿，并阻止切日串写。只有成功保存的内容能够保证关闭重进后保留。
- 待办及随想独立保存到 `timetable_todos`，当前使用 schema V3。V1/V2 读取本身不写盘；首次正常打开待办时安全迁移，旧未完成任务统一归入迁移当天，旧已完成任务优先归入执行日期、其次截止日期、最后实际完成日。旧备注、完成信息及内部旧时间字段保留，写入失败原样回滚；损坏和未知版本停止写入。现有课表 JSON 备份不包含待办或随想。
- 暂不包含：文件或教务系统导入、账号登录、云同步、消息提醒，以及待办与课程的自动关联。
- 待办与随想备份：在“设置 → 待办与随想备份”独立复制全部已保存记录为 JSON，粘贴后预览导出时间、V3 版本、日期范围、目标/完成数、随想篇数和本机将替换的数量，再确认整体覆盖。恢复前保留最近一份原数据，支持再次预览并恢复；不与课表备份混用，不提供合并。
- 恢复前必须处理尚未保存的目标与随想，可返回待办保存，或主动放弃修改。随想的“放弃修改”只在有未保存内容时出现，确认后保留已保存正文。恢复完成后再次进入待办会刷新目标、随想和月历，旧保存回调不能覆盖恢复结果。

## 本地运行

1. 安装 Node.js 24。项目通过 `.node-version` 和 `package.json#engines` 固定主版本，可先运行 `node --version` 确认结果为 `v24.x`。
2. 克隆仓库。
3. 在 `wechat-timetable` 目录按锁文件安装依赖：

   ```powershell
   cd wechat-timetable
   npm ci
   ```

4. 打开微信开发者工具，导入 `wechat-timetable` 目录。
5. 使用项目成员自己的微信扫码登录并编译。

如果需要使用正式 AppID 预览或真机调试，仓库管理员还需要在微信公众平台将协作者添加为项目成员。GitHub 仓库权限与微信小程序权限分别管理。

微信 API 类型定义由仓库内受版本控制的 `wechat-timetable/typings/` 提供，不依赖安装时额外下载另一份类型声明。升级类型定义时应单独审查对应文件并完成完整类型检查。

## 数据备份与恢复

1. 在课表主页点击“设置”，再进入“课表数据管理”。
2. 点击“复制课表备份”，把备份文本保存到可信位置。
3. 恢复时将完整 JSON 粘贴到输入框，点击“解析并预览”。
4. 核对预览中的课程、重复和冲突数量，再选择覆盖或合并。

覆盖、合并、恢复、数据迁移和课程作息保存前都会保留当前课表作为最近自动备份。当前课表使用 V5 数据结构：`groupId` 关联同一门课程的多个上课时段，`periodSettings` 同时保存全局作息规则、第一节起点、手动锚点、单节自定义时长和完整计算结果。V4 数据会从原有时间推断并保留午休锚点与单节时长，V1–V3 数据会生成默认九节作息。格式错误、字段非法、Storage 读取失败或版本不兼容时会停止写入并保留原数据；V1–V4 备份均可兼容导入。合并以整门课程为单位，任一时段重复或冲突时整组跳过，避免导入不完整课程。新版备份只有与当前课表采用相同学期和完全一致的课程作息时才能合并，不一致时请使用覆盖导入；未知更高版本会停止修改且不会降级写回。

课表 JSON 的导入和导出均限制为 1 MiB UTF-8 文本，超限拒绝且不截断；损坏的旧课表不会过滤异常课程后导出。读取最近备份只校验该备份，不触发当前课表迁移。解析后的覆盖/合并确认会核对本机课表是否变化，输入变更或离开页面使旧确认失效；恢复最近备份也会核对备份是否仍与展示内容一致。

普通课程修改、学期/作息保存、迁移及备份恢复，以及普通目标/随想保存，如果无法确认失败后的回滚结果，会暂停对应业务的本次会话写入。此时重试不能绕过保护，应保留备份并重新启动后检查。课表和待办使用各自的保护状态，互不影响。

格子归并、课程组事务、课程作息、备份、迁移、教学周、周次冲突、待办存储、项目文件完整性和全页面分享入口的自动化测试使用 Node.js 24 自带能力；TypeScript 固定为 5.9.3。完整检查会先执行真实类型检查，再自动发现各级测试文件，并执行带当前覆盖率基线门禁的全部测试：

```powershell
cd wechat-timetable
npm run check
```

需要单独查看覆盖率时运行 `npm run test:coverage`。当前门禁为行覆盖率 67%、分支覆盖率 77%、函数覆盖率 70%；这是防止覆盖率倒退的最低线，不代表微信页面交互已经由 Node.js 完整验证。

## 待办与随想备份恢复

1. 从课表主页进入“设置 → 待办与随想备份”，点击“复制备份文本”，将文本另存到可信位置。只导出已成功保存的记录，未保存草稿不在备份内。
2. 恢复时粘贴完整 JSON，点击“解析并预览”，核对日期范围、目标/完成数、随想篇数和本机数量。确认后替换全部日期的目标与随想；空备份会清空这些已保存记录。
3. 需要撤回时，在“恢复前备份”中预览并恢复。每次成功恢复都会保留恢复前的数据，始终只保存最近一份。它仍在当前设备上，不能代替另存到其他位置的 JSON。
4. 有未保存内容时，点击“返回待办处理”，保存目标/随想或主动放弃修改后再回来重新预览。读取失败、数据损坏或未知版本不会被当作空数据覆盖；V1/V2 用户先进入待办页完成原有迁移。

此功能沿用待办 schema V3，不修改课程 schema V5。独立备份封装使用 `kind: todo-journal`、`backupVersion: 1`，最近备份键为 `timetable_todos_recent_backup`。导入导出均限制为 1 MiB UTF-8 文本，超限拒绝且不截断。恢复前会验证原数据备份已落盘，目标写入后再次回读确认；失败时回滚待办与最近备份两个键。如果无法确认回滚结果，本次会话暂停待办写入，需保留备份并重新启动后检查。课表 JSON 不包含目标或随想；目标与随想 JSON 也不包含课表。

## 协作方式

数据版本按业务独立维护：课表当前格式为 V5，待办与随想为 V3，两类备份封装均为 V1。历史版本只用于识别、迁移和兼容导入，不按版本额外保存多套日常数据。当前模型、纯兼容转换和存储事务的边界，以及各版本的接受规则，见[数据版本兼容说明](./docs/数据版本兼容说明.md)。

- `main` 保存已经检查、可以继续测试的代码。
- 每项功能或修复使用独立分支。
- 开发完成后通过 Pull Request 审查并合并。
- 新增页面必须接入统一首页分享模块；测试会遍历 `app.json.pages` 检查好友与朋友圈回调，避免页面漏配。
- 只暂存当前任务涉及的明确文件，不使用 `git add .` 或 `git add -A`。
- 用户可见功能、依赖、启动方式或重要修复发生变化时，同步更新 README 和 `CHANGELOG.md`。

## 敏感信息

不要提交或发布以下内容：

- AppSecret、Access Token 或云开发密钥。
- 微信代码上传私钥。
- `project.private.config.json`。
- 管理员二维码、登录凭证和备案材料。
- 与开发无关的个人信息。
